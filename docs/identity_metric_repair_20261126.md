# 身份损失与独立评测分歧修复（2026-11-26）

## 已复现的根因

上轮 gain-only 训练在 160 次更新后正常早停：固定六人独立 SFace 从 0.774348 降至 0.769223，而训练代理 FaceNet 的 source cosine 从 0.834058 升至 0.841294。检查点、验证基准、数据身份划分和原生成骨干均正确，162 个非 gain tensors 完全未变。

重新生成四个验证身份（003、004、014、031）的相同左右转头/微笑，共 12 个编辑；图像、指令、种子均固定：

| 指标 | 原最佳 | 上轮结束 |
| --- | ---: | ---: |
| 独立 SFace | 0.764670 | 0.756719 |
| buffalo_l ArcFace（当时未用于训练） | 0.720139 | 0.708075 |
| FaceNet source，原曝光 | 0.802647 | 0.807687 |
| FaceNet source，曝光归一化 | 0.804545 | 0.808248 |
| 实际 FaceNet 加权目标 cosine（曝光归一化） | 0.796205 | 0.799063 |

这张表的 12 个编辑不同于常规六人 18 个编辑，不能混用两个均值。

裁剪隔离实验中，固定原最佳生成图的五点坐标后 SFace 仍下降 0.007873，接近重新检测时下降的 0.007951。FaceNet 改用与 SFace 相同的五点裁剪，仍上升约 0.004407。因此检测漂移不能解释主要分歧，换裁剪一项不足以修复。

未发现 RGB 顺序或梯度断链错误。FaceNet source/target 梯度平均 cosine 0.8307，没有证据表明 35% target 分量是主因；曝光归一化也具有其预期的曝光不变方向。旧 FaceNet 与新 ArcFace 在三个实例上的图像梯度平均 cosine 约 0.0566，迁移很弱，但并非逐例反向，不能据此断言每一次旧梯度都损害身份。

结论是旧代理不足以约束跨识别器的身份变化，优化它允许另两个识别器观察到的身份漂移。原始数据与裁剪、梯度隔离报告保存在 `outputs/identity_metric_repair_20261126/`。

## 本轮实现

- 新增显式 `identity_loss_backend`，旧配置默认仍为 FaceNet，新训练使用本地冻结 `w600k_r50.onnx` 的 source-only ArcFace。
- 使用官方 ONNX 解析器和固定 SHA256 校验，仅执行该已验证图的 Conv/PRelu/BatchNormalization/Add/Flatten/Gemm 六类算子。权重为冻结、非持久 buffers，不进入训练 checkpoint。
- 重新检测 source/generated 五点，按 ArcFace 112px RGB 契约对齐。检测和仿射参数停止梯度，连续 RGB 采样和识别器保留梯度；不对生成像素做 uint8 截断后再训练。
- identity reference 只取 source；目标图继续提供姿态/表情控制，避免把目标外观作为身份要求。ArcFace 使用原曝光，不沿用 FaceNet 的曝光归一化。
- 训练时若生成脸检测失败，可使用对应 source 五点对齐，回退数量明确写入日志；评测不代填分，检测失败记录空值、减少覆盖，禁止晋升。
- 验证按实际后端标注 ArcFace 指标，不冒充 FaceNet。SFace 识别器、权重、对齐方式和独立选择评分均未改变。
- ArcFace 与 FaceID 条件共用 w600k_r50，因此两者不是互相独立的识别器；独立泛化检查仍由 SFace 承担。
- 仍只允许原有 16 个有界身份 gain 更新，原生成、几何、mapper 和曝光权重保持冻结。恢复旧优化器不能静默更换身份 backend；更换目标使用 weights-only 初始化新 run。

## 实现验证

真实权重 PyTorch / OpenCV 同输入最大误差 1.33e-5，cosine 至少 0.99999994。包含连续裁剪与 OpenCV 量化插值差异的整条链路 cosine 至少 0.999843；真实生成图梯度有限且非零，source-copy loss 为零。可重跑 `arcface_cpu_parity.py` 及 JSON 保存在上述实验目录。

完整 CPU 测试及真实 GPU 全轨迹、独立身份/控制评测结果将在后台启动前核对。有限验证面板和短试训不能证明所有身份偏移已经消失。

## 验收与最终配置

仅更换 ArcFace 的 16-gain 对照未通过：带控制损失 16/32 步 SFace 为 0.774168/0.773464；仅身份目标的 16-gain 对照为 0.774037，均低于初始 0.774348。源/控制目标在一个真实完整采样案例中的 gain 梯度 cosine 为 -0.218；微笑样本的联合梯度规模也明显大于身份目标。不能把这归因于单一错误权重。

因此新增零初始化 private identity output rank2 残差，49,920 个可训练参数；原 16 个 gain 及 178 个既有 checkpoint tensors 全部冻结。它保留原 FaceID LoRA 路径和 bias 处理，允许调整身份输出方向，不修改通用 UNet、Q/K/V、mapper、几何、曝光和身份条件编码。此为受限容量修复，并非证明容量是所有分歧的唯一原因。

真实 GPU 检查确认训练与推理最终像素最大差 0、重载最大差 0；全部新参数梯度有限；原 checkpoint tensors 逐项不变。完整 CPU suite 171 项通过。
